# 告警复位 · OutageReset · HGame 009

> 游戏入口：http://127.0.0.1:43170/games/outage-reset/ · [统一启动说明](../../README.md)

十字翻转的熄灯谜题：每格是一盏告警灯，点一格会连带翻转自己与上下左右，把所有灯熄掉即完成。每局都保证可解，并给出理论最少步数。界面为原创，无外部字体、图片、联网或模型调用。

## 启动

需要 Node.js 22+，无需安装依赖。双击本目录 `启动游戏.bat` 打开游戏；已运行游戏库时会复用。也可在游戏库根目录运行 `npm start`，统一端口 43170。规则测试仍在本目录运行 `npm test`。如需临时更换整个游戏库端口，可在根目录设置 `$env:PORT=44170` 后运行 `npm start`。

## 玩法

1. 点击任意灯格：该格与上下左右四格一起翻转，边角只翻两到三格。
2. 再点一次会翻回去，点击次数不限，但步数越少越好。
3. 全部灯熄灭即通过，用时从第一次点击开始计算，通过后冻结。
4. 「重来本局」把灯盘恢复到开局状态但不换题，适合用来重刷步数。
5. 提示行里的「参考最少」是这盘的最少步数，用来判断自己绕了多少路。

三档规模（`minMoves` 是生成时要求的最少步数下限）：

| 范围 | 尺寸 | 最少步数下限 | 实测最优区间 | 开局亮灯 | 生成耗时 |
| --- | --- | --- | --- | --- | --- |
| 小型 | 5 × 5 | 3 | 3–6 | 6–17 | 0.10 ms/局 |
| 中型 | 6 × 6 | 4 | 4–8 | 8–20 | 0.10 ms/局 |
| 大型 | 7 × 7 | 5 | 5–10 | 12–26 | 0.15 ms/局 |

## 可解性与理论下限

把每格「按 / 不按」看成 0/1 变量，把「某格是否还亮着」列成方程：每格最终状态等于初始状态异或所有覆盖它的按法，于是整盘就是一个 GF(2) 上的线性方程组 `A x = b`。

- 高斯消元求出特解与零空间；枚举零空间的自由变量（三档分别是 2、0、0 维），取汉明重量最小的解，就是这一盘的**理论最少步数**，也就是界面上的「参考最少」。
- 5×5 时矩阵秩为 23（零空间 2 维），所以**任意局面里只有约 1/4 可解**：实测随机 300 盘有 217 盘无解。6×6 与 7×7 满秩，任意局面都可解。
- 生成器不是随机撒灯，而是先随机按若干格得到一个必然可解的局面，再用解算器复核「可解且最优步数不低于下限」，因此开出的题一定有解，这一条由测试与 `npm run probe` 双重覆盖。

## 计时与战绩

- 每档分别记录最快用时与最少完成步数，记录里同时保存该盘的参考步数，便于对比自己离最优差多少。
- 战绩保留最近 50 条，同一局只记一次，刷新或重复结算不会重复计数。
- 时间按 `startedAt` 与 `finishedAt` 的真实时间差计算，精度到秒。

## 存档

- `outagereset-save`：当前一局，含当前灯盘、开局灯盘、步数、理论步数、状态、开始与结束时间。
- `outagereset-records`：最近 50 条战绩，含范围、尺寸、秒数、完成步数、参考步数与完成时间。
- `outagereset-view`：上次使用的视图模式。

`validSave` 校验版本、范围、灯盘与开局灯盘的长度和取值（只能是 0 或 1）、步数、理论步数、状态与时间戳：`ready` 必须零步且当前灯盘等于开局灯盘，`playing` 必须已走过步数、没有结束时间且尚未熄灭完，`won` 必须已全灭。

## 结构

- `server.mjs`：统一游戏库启动入口，复用根目录服务。
- `public/engine.js`：无 DOM 依赖的规则内核：邻居表、翻转、GF(2) 高斯消元与零空间枚举、最少步数、生成器、开局、落子、重来、计时、存档校验、战绩汇总。
- `public/app.js`：界面渲染、点击与键盘操作、重置、对话框、存档读写、双视图文案。
- `../../shared/quiet.js`、`../../shared/quiet.css`：直接引用共享实现，不再维护副本。
- `public/style.css`：标准（深色告警盘）与清零两套主题。
- `scripts/probe.mjs`：三档的随机局面可解率、生成耗时与最优步数区间抽样。
- `test/engine.test.mjs`：规则测试。

## 验证

`npm test` 共 11 项：十字邻居在中心、边、角分别是 5 / 4 / 3 格；解算器给出的按法能把灯盘清空且步数与按法长度一致、无重复格；5×5 既能找到可解局面也能找到无解局面，全灭局面最少 0 步、单灯局面在 5×5 上判无解；随机构造的局面最优步数不超过实际按下的次数；三档生成结果必然可解、非全灭、最优步数不低于下限且可复算；落子翻转十字形状、计步并在首步启动计时，越界抛 `index`；熄灭最后一盏后进入 `won` 且时钟冻结，结束后继续操作抛 `ended`；重来把灯盘恢复成开局并清零步数；存档校验拒绝非法尺寸、非 0/1 灯盘、被篡改的开局灯盘、`playing` 带结束时间、未熄灭却标记 `won` 等畸形存档；同一局只记一条并按档汇总最佳用时与最少步数；三档范围的尺寸与最少步数下限一致。

`public/engine.js` 不碰 DOM，`public/app.js` 只负责显示与交互。
