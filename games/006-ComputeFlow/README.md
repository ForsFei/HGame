# 算力调度站 · ComputeFlow · HGame 006

> **统一入口（已整理）**：从游戏库根目录双击 `启动游戏库.bat`，地址为 `http://127.0.0.1:43170/`；本游戏地址为 `http://127.0.0.1:43170/games/compute-flow/`。本目录的 `启动游戏.bat` 和 `npm start` 也使用同一个游戏库服务。旧独立端口已停用，下面旧版记录中的端口仅供历史参考。无需单独启动此游戏。


挂机养成小游戏：算力随时间自动累积，用它逐个扩容节点，解锁更快的产出。关掉页面也按真实时间继续累计，适合摆在一边偶尔看一眼。无外部资源、联网或模型调用。

## 启动

需要 Node.js 22+，无需安装依赖。双击本目录 `启动游戏.bat` 打开游戏；已运行游戏库时会复用。也可在游戏库根目录运行 `npm start`，统一端口 43170。规则测试仍在本目录运行 `npm test`。如需临时更换整个游戏库端口，可在根目录设置 `$env:PORT=44170` 后运行 `npm start`。

## 玩法

1. 初始有 2 个工作线程和少量算力，产出 2 点/秒。
2. 点「扩容」花算力为某个节点增加一个实例，产出立刻提高。
3. 同一节点每满 10 个，该节点的产出再 +25%，算力数字后面会显示当前倍率（如 ×1.25、×1.50）。
4. 还没解锁的节点初始成本更低，优先补齐通常比一直堆同一个节点更快。
5. 右侧「下一个目标」会显示距离最近的未解锁节点和进度条。

八个节点：

| 节点 | 初始成本 | 单个产出 | 说明 |
| --- | --- | --- | --- |
| 工作线程 worker-01 | 10 | 1 | 基础执行单元 |
| 消息队列 queue-02 | 120 | 6 | 削峰与解耦 |
| 倒排索引 index-03 | 1.5K | 32 | 检索加速 |
| 分布式缓存 cache-04 | 18K | 170 | 热点驻留 |
| 分片集群 shard-05 | 110K | 1.3K | 横向拆分 |
| 推理节点 gpu-06 | 1.3M | 8K | 批量计算 |
| 量子单元 quantum-07 | 12M | 45K | 实验性扩容 |
| 算力网格 grid-08 | 140M | 260K | 全局调度 |

每个节点的价格按 1.15–1.22 的倍率递增，越往后越贵。按贪心策略模拟，约 2 分钟解锁消息队列、5 分钟解锁倒排索引、15 分钟进入分布式缓存、30 分钟进入分片集群，一小时左右摸到推理节点；最后两级需要更长时间。

## 离线与自动扩容

- 关闭页面后按 50% 效率继续累计，最多补 8 小时，回来时页面顶部会提示补齐了多少。
- 「自动扩容」开启后每秒自动买当前最便宜的一档。它只是省手，不会做出更聪明的选择。
- 进度每 5 秒自动保存，关闭标签页时也会保存一次。

## 简洁模式（摸鱼模式）

点击「简洁模式」或按 **Alt+M**，切换为浅色等宽的配额监控台：标题变成「配额监控」，标签页改为「配额监控 · 本地」，隐藏品牌与装饰，直角、无阴影。整页看起来就是一张资源用量表。

术语全部落在运维与资源监控领域：

| 标准模式 | 简洁模式 |
| --- | --- |
| 算力调度站 | 配额监控 |
| 总算力 | 已用配额 |
| 产出 | 吞吐 |
| 节点 | 实例 |
| 数量 | 副本 |
| 扩容 | 扩容 |
| 下一个目标 | 待初始化 |
| 运行概况 / 累计产出 | 运行概况 / 累计吞吐 |
| 调度建议 | 容量建议 |
| 重置 | 清空配额 |
| 离线 2 小时，补齐 +12K 算力 | 离线 2h 0m，补齐 +12K 吞吐配额 |

节点名会换成 `worker-01`、`queue-02` 这类资源标识，下面小字是用途（基础执行单元、削峰与解耦…），仍然是给人看的，不需要先懂术语。切换不改变进度，模式记在本地。

## 存档

`computeflow-save` 保存节点数量、当前算力、累计产出、自动扩容开关和最后活跃时间；`computeflow-view` 记录视图模式。存档格式异常时自动开始新局。清空配额会删除全部数据，不含联网排名。

## 结构

- `server.mjs`：本地静态服务，只监听 `127.0.0.1`。
- `public/engine.js`：节点表、价格与产出计算、里程碑加成、时间结算、离线补齐、自动扩容、存档校验、数字格式化。
- `public/app.js`：界面渲染、增量刷新、自动扩容循环、双视图切换。
- `public/style.css`：标准视图与配额监控视图两套主题。
- `scripts/simulate.mjs`：贪心策略模拟，用于检查解锁节奏。
- `test/engine.test.mjs`：价格曲线、里程碑、产出求和、购买限制、按时间结算、离线效率与上限、自动购买、目标选择、存档防篡改与格式化。

## 验证

`npm test` 共 11 项测试：价格按倍率递增；每满 10 个实例产出 ×1.25；总产出等于各节点之和；购买扣除算力、余额不足与未知节点被拒绝；`tick` 按真实时间差结算且时间回退不会倒扣；离线按 50% 效率、8 小时封顶；自动扩容在买不起时停止且遵守次数上限；目标指向最便宜的未解锁节点；存档被篡改（负数、非整数、非法开关、未来时间）时 `validSave` 返回否；恢复后从同一速率继续；数字格式化覆盖 0、小数、K/M/B/P 与非法值。

界面按真实时间差结算，标签页被浏览器节流时不依赖定时器累加，切回来能一次补齐。
