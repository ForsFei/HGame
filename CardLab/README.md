# 纸牌工坊 · CardLab

受扑克构筑玩法启发的原创简易小游戏。单人 8 阶段、14 种原创效果模块、关间商店、牌型升级和自动存档。不使用《小丑牌》的美术、音乐、文案或代码。

## 启动

需要 Node.js 22+，无需安装依赖。双击 `启动游戏.bat`，打开 <http://127.0.0.1:43171>；关闭命令窗口停止服务。也可运行 `npm start`。端口冲突时，PowerShell 中设置 `$env:PORT=43172` 再运行 `npm start`。

## 玩法

每阶段按所选牌组重新洗牌，抽 8 张。选择 1–5 张提交或弃掉补牌。每阶段最多出牌 4 次，达到目标就立即过关，否则机会用完后失败。标准难度的 8 阶段目标为 150 / 300 / 500 / 800 / 1200 / 1800 / 2800 / 4200，各阶段分数独立。

## 起始牌组与难度

v4 起的新局可选以下牌组，开局前会显示牌组说明和八关目标：

| 牌组 | 构成 | 每阶段弃牌 | 特点 |
| --- | --- | --- | --- |
| 经典 | 完整 52 张，无大小王 | 3 次 | 包含全部点数与模块 |
| 精简 | 移除 2、3，共 44 张 | 3 次 | 高点数更集中，无法组成 A2345 等低位顺子 |
| 数字 | 移除 J/Q/K，共 40 张，保留 A | 2 次 | 商店不出售无法触发的「肖像收藏」 |

休闲、标准、挑战难度分别采用标准目标的 80%、100%、130%，其他计分、奖励和商店价格相同。牌组与难度保存到当前进度和战绩中；战绩可分别筛选，避免把不同配置的成绩混在一起比较。这些配置提供不同构筑路线，尚不代表各牌组胜率相同。

v1–v3 存档继续采用原有经典牌组、标准目标与对应版本规则。v3 历史种子重开锁定原配置；v4/v5 再次挑战默认恢复原牌组、难度与版本，也可在确认前修改配置。

支持高牌、一对、两对、三条、顺子、同花、葫芦、四条、同花顺；A2345 可作为顺子。顺子、同花、葫芦、同花顺须选择满 5 张。高牌只计最高一张，一对等重复组合只计构成组合的牌，其余牌不触发计分效果。A 点数为 11，J/Q/K 为 10。

得分 =（牌型基础筹码 + 计分牌点数 + 模块筹码）×（牌型基础倍率 + 模块倍率），最后处理乘法模块，向下取整。预览就是实际提交时的得分。

通过阶段获得 $5 + 剩余出牌次数 + 利息（过关前资金每 $5 提供 $1，最多 $5），随后进入商店。购买模块、升级随机提供的两种牌型或花 $3 刷新整组商品；每个商品每次展示只能买一次。牌型升级持续本局，最多持有 5 个不同模块，只能在商店出售，卖价为原价的一半向下取整。不购买也可进入下一阶段。

## 商店换货与模块替换

v5 新局整局首次刷新免费，之后每次 $3。免费次数只提供一次，跨关卡、刷新网页和自动存档保留使用状态；新开一局或同种子重新挑战才会重置。v1–v4 存档及历史种子挑战仍按原规则每次收取 $3，不会中途获得免费次数。新局配置窗口会标明对应规则。

持有 5 个模块后，商品按钮改为「替换配置」。选择商品会打开替换面板，列出各旧模块效果、卖价抵扣、补差和成交后余额。点击旧模块即确认替换，一次完成出售和购买；取消或按 Esc 不会改动资金与模块。不足以支付补差的选项禁用，成交后新模块保留在原槽位，模块总数仍为 5。旧版本也可使用这项交易便捷操作，其经济效果等同于先卖后买。

## 特殊关卡与结算明细

新建游戏采用新版规则：第 3 关「褪色」让红桃、方块计分牌的点数归零，但它们仍构成牌型、触发模块；第 6 关「满手开局」首次出牌必须选 5 张，弃牌不受限制，之后可正常出 1–5 张；第 8 关「变奏」对本关重复使用的牌型在所有模块结算后乘 0.5，最终向下取整。阶段规则在牌桌与商店下一阶段预告中显示。

旧版存档继续使用经典规则直到结束；新建一局才启用特殊关卡，避免中途改变原有对局。选中的牌会标记「计分 / 不计分」；简洁模式对应「计入 / 不计入」。预览与上一手结果都提供可展开的结算明细，包含牌型基础、实际牌点数、模块加成与阶段调整。

## 简洁模式

点击「简洁模式」或按 **Alt+M**，变成“组合收益分析”工作台。花色显示 S/H/C/D，牌显示为数据样本；效果牌变为编号模块，牌型使用中性名称。切换保留选择与进度，刷新记住模式。无音效、无外部资源。简洁模式不隐藏地址栏、浏览器历史或系统任务栏。

自动保存一个进度到当前浏览器 localStorage。商店商品与余额也会保存；新建一局需确认，会覆盖当前存档。存档格式异常时开始新局。完全离线，不含模型调用、付费功能或远程联机。

## 种子重玩与本地战绩

新建时可输入 1–24 位字母、数字或短横线组成的种子编号，留空自动生成。编号会转为大写。相同规则版本、牌组、难度、种子和操作可复现牌序、商店与后续阶段；不同操作仍可能改变商品内容。牌堆与商店采用独立随机流，刷新商店不改变下一阶段牌堆，刷新页面不改变后续随机结果。

点击编号旁的「同种子重开」，或从「本地战绩」再次挑战，确认后开启新的尝试。最近 50 次完成或失败的对局保存在浏览器，包含规则版本、编号、到达阶段、累计得分、最高单次得分和最终模块；刷新终局页面不会重复记账。中途放弃的局不算一条完成战绩。累计得分为已过关分数加失败阶段分数，不是最终关卡分数。旧版存档没有可复现编号，也无法补回历史单次最高分。

v3 新局把「轻装」倍率加成调为 +6，「共振」筹码加成调为 +100。旧存档保持旧数值。检查方法、样本结果与限制见 [BALANCE.md](BALANCE.md)。

## 验证

`npm test` 检查所有牌型、A 的边界、计分牌、模块叠加、交易限制、阶段转换及存档，还覆盖九种开局配置、实际过关阈值、数字牌组的最大补牌消耗、商店过滤和 v3 种子兼容。商店测试覆盖 v5 免费次数持久化、旧版付费规则、抵扣交易及失败操作的原子性。`public/engine.js` 为独立规则模块，`public/app.js` 为交互界面，`server.mjs` 只提供本地静态文件。
